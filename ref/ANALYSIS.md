# 参考视频逐帧分析（Domino Cafe 麻将消除广告）

源视频：360×640，30 fps，约 56 s。分析方法：`ffmpeg -vf fps=10` 抽取 0–20 s 共 200 帧（`ref/dense/`），
关键时刻再以 30 fps 抽帧并裁剪放大（牌面、托盘、配对飞行、爆开、字母入槽），另以 1 fps 浏览 20–56 s。
下文时间均为视频时间；比例均以“牌面宽 w”为单位。

| 项目 | 视频实测 | 工具默认值 |
|---|---|---|
| 顶栏（木纹） | 0 – 0.117H，深棕木纹，底部亮/暗两道边线 | `topBarHeight 0.118` |
| Logo | 左侧 0.01–0.31W，金色 “online / DOMINO / Cafe”，无红色飘带 | `logoRibbon false` |

| 背景 | 纯黑（中心极轻微暖色） | `bgColor #0a0503 / bgColor2 #000` |

## 2. 相机与牌的造型
* **相机：纯俯视、无透视**。所有牌的正面是完全对齐的矩形，没有近大远小，也没有倾斜（旧版默认 22° 倾角是错误的）。
* 牌的“厚度”通过 **2.5D 侧面露出** 表现：每张牌正面的**下方**露出一条白色侧面 + 一条绿色底座，**右侧**露出一条很细的绿色边。
  上层牌相对下层牌整体向左上偏移这一段露出量，看起来像斜 45° 的“柜式”投影。
  * 下方露出总量 ≈ 0.09w（其中白色侧面约 60%，绿色底座约 40%）。
  * 右侧露出 ≈ 0.03–0.04w（几乎只见绿色）。
  * 工具实现：正交相机 + 对棋盘做剪切变换（z 越高越向左上偏），`sideRevealY 0.09`、`sideRevealX 0.035`、`baseRatio 0.4`。
* 牌面：宽:高 ≈ 1 : 1.18（正面，不含露出），圆角 ≈ 0.10w，颜色接近纯白 `#f6f6f0`，自上而下有轻微亮→暗渐变，没有明显倒角高光。
* 侧面颜色：白色侧面 `#deded4`（比正面略灰），底座绿 `#3aa655`（中绿，偏亮），最底一圈略深。
* 阴影：牌左侧/下方有柔和黑色投影落在下层牌上，偏移约 (-0.07w, +0.03w)，在纯黑背景上几乎只表现为边缘变暗。→ `shadowDX -0.07, shadowDY 0.03, shadowStrength 0.5`。
* 牌间隙：横向 ≈ 0.03w，纵向几乎无缝（行与行之间只隔着下方露出的白边+绿边）。
* 牌面图案：比旧版大且粗，汉字为粗黑体（非楷体）：南/北/東 黑色，中 红，發 绿，二/八/伍/四/三 藏青；字母 R/L 藏青、E/T 红、A/X 绿，粗无衬线体；
  另有筒子（藏青/绿/红圆环）、条子、红花/兰、彩色鸟、京剧脸谱、奶牛等插画牌。

## 3. 布局（层与错位）
* 可见顶层是 **6 列 × 8 行的砖块式排列**：奇数行相对偶数行向右错开半张牌（行首交替出现在左侧/右侧）。
* 顶层几乎没有空位；下层牌只在行尾“半张牌”处露出，以及顶层牌被消掉后露出。
* 被压住（不可点）的牌：**视频中没有明显的压暗**，只靠被上层遮挡来表现；露出部分亮度约降低 10–20%。→ `blockedDarken 0.18`。
* 工具默认：`layers 3, baseCols 6, baseRows 8, shrink 0, offsetX 0.5, offsetY 0, altOffset true, rowStagger 0.5, holeRate 0`（新增“奇数行横向错位”参数）。

## 4. 交互时序（逐帧）
### 4.1 开场（0.0–2.6 s）
| 时间 | 画面 |
|---|---|
| 0.0–0.4 | 正常棋盘，托盘空 |
| 0.5 | **整个棋盘区域变暗**（约 45% 黑色覆盖），托盘不变暗 |
| 0.6 / 0.8 / 1.0 / 1.2 / 1.4 | 托盘中依次弹出 R、E、L、A、X（每 0.2 s 一个，带小幅放大回弹），字母牌占满格子，用各自颜色 |
| 1.4–2.4 | 静止展示 RELAX |
| 2.4–2.6 | 字母淡出，棋盘恢复亮度 |
→ `introDelay 0.4, introStagger 0.2, introDuration 2.2, introDim 0.45`。

### 4.2 第一次点击（选中）
* 3.3 s 手指点下右下的“鸟”牌，**3.4 s 该牌原地变绿**：牌面从左下角向右上角叠加浅绿渐变（左下最浓，右上透明），绿边框，侧面变绿。
* **不放大、不抬起、不移动**，一直停在原位等待第二张（3.4–4.6 s 共 1.2 s 保持绿色）。
* 7.9 s 第二轮同样：点击后 0.1 s 内变绿，停留至 9.3 s。
* 点击处**没有黄色波纹**（视频为真人手指，按下时手指略缩小）。~~工具默认无手指图，故仍保留可关的点击波纹作为点击提示。~~ v14 起波纹默认关闭，改为牌本身的“按下”效果（见文末“第九轮：点击按下”）。
* ~~不放大、不抬起、不移动~~ → 第九轮逐帧复核：点击瞬间牌会**缩小并下沉**（像按钮被按下），见文末。

### 4.3 第二次点击 → 两张牌飞行汇合（不进托盘）
* 4.6 s 点击第二只“鸟”。4.7 s 起**两张牌同时**脱离棋盘（原位置立刻露出下层牌），整体染绿，放大到 ≈1.25 倍并带投影。
* 路径：每张牌**先向外侧（远离两牌中点、朝屏幕边缘）飞出**，再沿弧线回到中间汇合：
  * 上方的鸟：4.7→5.0 s 飞到左上角屏幕边缘，5.0→5.6 s 沿左边缘下行，5.6→5.8 s 向右进入中间；
  * 下方的鸟：从右下飞出到右边缘外侧，再向左上收拢；
  * 27.4–28.0 s 的 T 对也一样：一张飞出到左边缘，一张飞出到右边缘，再在中间并排。
* 汇合点：~~两牌中点并向棋盘中心靠拢~~（第一轮的判断有误，见文末“第四轮复核”：所有配对都在画面固定位置汇合）。两张牌**左右并排紧贴**。
* 时长：点击后约 1.1 s 到达（4.7→5.8 s），全程缓入缓出。→ `flyDuration 1100, flyScale 1.25, outwardAmount 0.9, meetCenterPull 0.5`。

### 4.4 爆开消除
* 5.9–6.3 s：深绿/浅绿的**细长尖叶**（柳叶/竹叶形，长 ≈0.4–0.5w，约 10–14 片）围绕两张牌**旋转着向外散开**，部分叶片压在牌面上。
* 这段时间牌保持放大（6.3 s 再略放大到 ≈1.3 倍）。
* 6.4 s 牌迅速缩小，6.5 s 缩到约一半并淡出，6.6 s 完全消失。爆开总长 ≈0.7 s。
* 没有白色闪光圈。→ `burstDuration 700, particleCount 12, particleSize 1.4, particleColor #2e7d32, particleColor2 #7cc576`。

### 4.5 目标字母
* **字母牌也是成对出现的**（棋盘上有两张 X、两张 E、两张 A……），玩法和普通牌完全一样：点两张同字母 → 飞出汇合 → 爆开。
* 14.0–15.6 s：两张绿色 X 配对爆开；15.8 s **X 出现在托盘第 5 格**（伴随一小圈绿叶），之后一直留在托盘中。
* 不在单词里的字母（视频中的红色 T）配对后只是普通消除，不进托盘。
* 托盘中的字母牌与棋盘牌同款外观（白面、绿底边），几乎占满格子。
* 收集顺序：E、X、A、L、R（46–51 s 才收集到 R），中间穿插消除若干普通牌对，用来解放被压住的字母。
→ 新增 `letterMode: pair`（默认），字母配对爆开后飞入对应格子（`letterFlyDuration 220`）。

### 4.6 RELAX 完成与结束页
* 51 s 最后一对 R 配对，托盘集齐 RELAX；约 1 s 后（52 s）**直接切到结束页**，棋盘上还有大量牌。
  → 视频的通关条件是 **集齐目标单词**，而不是清空棋盘。新增 `winCondition: word`（默认）/ `clear`。
* 结束页：深绿径向渐变背景，顶部挂着灯串和星星；中间带金边的 App 图标（背后有黄绿色光晕）；
  金色描深红边的 “Domino Cafe” 标题；带金边的绿色胶囊按钮；手指点击按钮。

### 4.7 其他观察
* 27.8–28.3 s 两张 T 汇合时，画面四周出现一圈细红边框、托盘格也泛红（推测为广告剪辑叠加的强调效果，与玩法无关），未复刻。

## 5. 旧版与视频的主要差异（已修正）
1. 相机有 22° 倾角+透视 → 改为正交纯俯视 + 右下 2.5D 侧面露出。
2. 牌偏厚、绿底座过宽、牌面偏黄、圆角偏大 → 按上表调整比例与颜色。
3. 金字塔式层叠（每层缩一圈、上下左右各错半张）→ 6×8 砖块式顶层，层间只横向错半张。
4. 点击后牌放大浮起成精灵 → 原地变绿，不移动。
5. 配对直线飞向中点 → 先向外飞出再弧线汇合，放大 1.25 倍，约 1.1 s。
6. 爆开是圆形叶片四散下落 + 白色闪光 → 细长尖叶环绕旋转散开，牌先停留再缩小淡出，无闪光。
7. 字母是单张、点击直接飞入托盘 → 字母成对，配对爆开后入槽。
8. 必须清空棋盘才结束 → 集齐 RELAX 即结束（可切换）。
9. 开场只是在托盘显示单词 → 棋盘压暗 + 字母逐个弹出 + 停留 + 淡出。
10. 自动通关不考虑字母 → 优先消除压住目标字母的牌，并按概率穿插无关配对（`extraPairChance`）。

## 第三轮复核（牌面构成 / 取景 / 筒子）

参考 t=0.2s 顶层可见 46 张的统计：字母 12（R E L A X 各一对 + 红色干扰 T 一对，约 25%）、插画/花 10（蓝框牛×2、鸟×2、红梅、红兰、戏曲女孩、红脸谱×2、叶纹圆章）、
数字 6（二三四伍八）、字牌 7（中 發 東 南 北）、筒子 7（三筒斜排 绿/红/藏青、四筒、八筒两列）、条子 4（细绿条，2/3/4 条）。没有任何一种牌面超过 2 张。

修正：
- 牌面按类别权重交错分配（插画 0.29 / 数字 0.18 / 字牌 0.20 / 筒 0.20 / 条 0.12，可在面板调整），同类内轮换，单一牌面全盘最多 6 张；字母组（目标 + 干扰）在生成时优先占最高层，所以顶层固定出现 RELAX+T 各一对。
- 插画重画：蓝色圆框“牛”（浅蓝头巾、粉色大鼻、两侧浅蓝耳）、藏青月牙身体 + 红头橙嘴 + 浅橙翅膀 + 绿条的鸟、金色圆框戏曲女孩、红框绿盔脸谱、红色细圈叶纹圆章、五瓣红梅（白心）、红兰（三大瓣两内瓣）。熊猫/金鱼/菊/粉花/白板等不在视频中的牌面移入“额外插画”开关（默认关）。
- 字母：900 字重 + 同色描边加粗，字号约牌宽 0.92，横向略加宽。
- 筒子：改为粗圆环（中心留白），三筒 绿/红/藏青 斜排，四筒 1 绿 3 藏青，八筒两列藏青 + 中间红。条子更细。
- 取景：各层几乎正对叠放（层偏移 0.08 牌宽，只在右侧露出细边，不再露出半张牌的整列）；棋盘缩放 0.86、上下偏移 0.068、左右偏移 0.005，顶行 y≈268/958、左边距≈38px，与参考（265、40）基本重合。

精确量取（30 fps 单帧 + 10 px 网格）的是 #1 #3 #5 #6 #7 #11；其余由 5 fps 总览和汇合帧估读（标 ≈），误差约 ±0.1 s / ±5 px。

结论：

* **汇合点固定**：无论两张牌在棋盘哪里，11 次全部在同一位置汇合——两牌并排的中心约 (169, 375)/(360×640) = **(0.47 W, 0.586 H)**，即顶部托盘以下游戏区域的中心（略偏左）。不是两牌中点。两张牌左右并排紧贴，左边的牌在左。
* **弧线**：按两牌的左右关系分配方向：靠左的那张先**水平冲向左侧屏幕边缘**（可略出屏），靠右的冲向右边缘，同时略微上扬（约 0.03 H）；然后沿边缘转向汇合点的高度，最后水平收进中间——形如“C / 反 C”。例：T 对右上那张 27.6–28.0 s 冲出右上方屏外再从右侧落回；左边那张 27.5–27.7 s 贴到左边缘、28.2 s 起向右收拢。鸟对上面那张贴左边缘下行，下面那张贴右边缘上行。
* **时长与缓动**：第二次点击 → 汇合约 **1.0–1.07 s**；沿弧线的进度接近**匀速**（+750 ms 时两张牌仍在屏幕两侧，最后 300 ms 才收进中间），不是先快后慢。
* **缩放**：起飞时 1.0（与棋盘上的牌同大），飞行前段迅速变大：+0.2 s ≈1.2、+0.7 s ≈1.5、汇合时 ≈**1.6**（棋盘牌面宽约 44 px，汇合时每张约 70 px，高约 88–90 px vs 55 px）。汇合后停在中心期间只再**轻微放大约 +3–5%**（这就是“只放大一点点”的阶段），随后约 0.15 s 内缩小并消失。注：相对棋盘上的牌，汇合时的大小实测约 1.6 倍，比我们之前的 1.25 还大；“只放大一点”对应的是汇合后的那段（+4%）以及整个过程中牌不会变成巨大的特写。
* **旋转**：无，全程保持水平。
* **消除时序**：汇合瞬间绿叶开始旋转散开；在中心停留约 0.5 s（缓慢放大 +4%），然后 0.15 s 缩小淡出，总计约 0.7 s。
* **字母对**：与普通牌**完全相同**——同样弧线飞到画面中部汇合、绿叶爆开。中心那对缩没的同一帧（如 X：15.77–15.80 s），对应字母**直接在托盘格里弹出**并带一圈绿叶，30 fps 下看不到任何从中心飞往托盘的中间帧。干扰字母 T 消失后不进托盘（此时边框与托盘泛红）。

对应修改（v5 默认值）：

| 参数 | 旧 | 新 |
|------|----|----|
| `meetMode` 汇合点 | 两牌中点+向中心靠拢 | `screen` 画面固定位置（可切回 `pair`） |
| `meetX` / `meetY` | — | 0.47 / 0.588 |
| `arcBend` 弧线弯曲 | （outwardAmount 0.9 牌宽） | 1（冲到屏幕边缘外 5%，0 = 近似直线） |
| `flyEase` | 三次缓入缓出 | `linear` 匀速 |
| `flyDuration` | 1100 | 1050 ms |
| `flyScale` 最大放大 | 1.25 | 1.6（前段增长快：1-(1-t)² 曲线） |
| `meetGrow` 汇合停留放大 | 6% | 4% |
| `flyRotate` | — | 0（视频无旋转，可设） |
| `burstDuration` | 700（45% 放大+30% 消失） | 700（76% 停留放大 + 24% 缩小消失） |

## 第五轮复核：逐牌细节（v8）

方法：`test/replica.mjs` 把我们顶层 48 张牌按参考 t=0.2s 的排布逐格复刻（取景已对齐，所以同一像素矩形就是同一张牌），再逐牌 3 倍放大并排对比，并沿牌边做 1 px 步长的像素剖面。参考视频原始分辨率只有 360×640，放大后天然偏糊。

### 牌身（720×1280 坐标）

## 第七轮复核：层的结构与层次可读性 (v10)

### 参考视频里下层是怎样的（0.2 / 22 / 40 / 45.5 / 49 / 51.7 s 抽帧，裁出被消除位置，见 `screenshots/compare_holes.jpg`、`compare_holes_zoom.jpg`）
* **下层与顶层同一套砖块位置、同样大小**，没有经典麻将接龙那种错开半张；拿掉一张顶层牌后，下面露出的牌就在原位（如 E→鸟、T→5 筒、X→条子、鸟→二）。
* **下层比顶层窄**：顶层最左/最右两列（含错位后的边缘牌）下面是空的，拿掉后直接露出黑色背景（例：第 1 行最左牛、第 2 行最左 X、第 6 行最右 E 被拿掉后都是黑洞）；中间位置下面才有牌。→ 每低一层每侧少一列（`insetX = -1`），顶层边缘牌允许“悬空”。
* **下层牌面向右下错开约 1 个牌厚**：40 s 的“二”(下层) 与同一行的“八”(顶层) 比较，上沿低 ≈3.5 px、横向右移 ≈2 px（360 宽原片，牌宽 45 px）→ 0.045 / 0.075 牌宽。正是 2.5D 视角下“低一层 = 离镜头远一个牌厚”的自然效果，也是肉眼分辨层次的主要线索。
* **下层牌更暗**：露出的“二”牌面 RGB≈231，顶层“八”≈244，约暗 5–6%（“二”本身未被压住，所以这是按深度的变暗，不是“被压住变暗”）。
* **上层牌对下层有投影**：“八”左边缘在“二”上留下一条暗边；上一行顶层牌的白色侧面/绿色底边直接盖在下层牌的上沿。
* 部分被压住的下层牌：只露出右/下的一窄条，同样偏暗。

### 我们 v9 的问题（分层调试 `screenshots/layers_debug.jpg`、对比 `layers_readability.jpg`）
1. **层间错位被完全抵消（主要原因）**：`revealCompensate` 把 2.5D 剪切造成的层间偏移 100% 抵消，三层牌面在屏幕上**像素级完全重合**（实测下层与上层同位置牌的屏幕偏移 = 0）。拿掉顶层牌后，下面那张出现在一模一样的位置、一样亮，看起来像“牌没被消掉/换了张脸”，完全看不出它在第几层。
2. **三层同样大小 6×8**：任何位置拿掉都会露出下一张，永远没有空洞，与参考（边缘拿掉是黑洞）不符；全盘 144 张，参考约 96 张量级。
3. **没有按深度变暗**：只有“被压住”才变暗（0.18），露出的下层牌和顶层一样亮。
4. **上层对下层的投影几乎看不见**：投影贴图的实心部分与牌一样大，只偏移 0.07/0.03，大部分藏在牌身下面。
5. **砖块奇偶错位 bug**：居中模式下层行数与顶层相差偶数行（如 insetY = 1）时，砖块错位按各层自己的行号算奇偶，对齐的行正好反向错开半张——下层整行从上层缝隙里斜着露出来（node 检查：v9 insetY=1 时 648/648 对同行牌全部反向错位，v10 为 0）。
6. 下层变窄时旧的“去掉悬空牌”逻辑会把顶层边缘牌删掉（v9 用 insetX=-1 只剩 48 张）；`layers` 大于可容纳层数时 `layerGrids` 直接 break 得到空棋盘。
* 已检查、没有问题：正交相机下深度/渲染顺序正确（下层侧面不会画到上层牌面上，阴影四边形与下层牌面相差 0.001 无 z-fighting）；点击命中取命中物中最高层；被压判定（逻辑坐标重叠 97%）与画面一致——下层牌向右下错开后被相邻行顶层牌视觉上盖住约 0.027 牌宽，小于参考可感知范围，仍判为可点，与参考一致。

## 第八轮：金字塔堆叠 (v11，用户要求)

用户要求默认改为真正的金字塔：底层最大，每往上一层变小并居中压在下层上，从上往下看每层外圈都露出来。

### 试验（`test/pyramid-shot.mjs`，720×1280 画布）
| 方案 | 结论 |
|------|------|
| 每圈 1 整张 + 无砖块错位 | 上层牌正好落在下层牌的格子上，看起来像一整块平的 7×8 网格，层次只能靠变暗分辨，**不清楚** |
| 每圈半张 + 砖块错位 0.5 | 上下层错位方向混杂，边圈呈锯齿，凌乱 |
| **每圈半张 + 无砖块错位（选用）** | 上层每张牌压在下层两张（四张）之间，边圈规整，台阶一眼可见 |
| 加强对称阴影（扩散 2、强度 0.95、阴影中心对准牌身含侧面） + 逐层变暗 0.15 | 每层外围有一圈柔和投影，层次最清楚 |

### 左右/上下平衡
* 2.5D 侧面只向右下露出。若每层再整体向右下错开 o，下层露出的边圈（含其侧面）左边 = 缩进−o、右边 = 缩进+o，不可能同时左右等宽。所以金字塔模式下开 `ringBalance`：层与层（牌面+侧面）以同一中心叠放，各层边圈左右、上下严格等宽；立体感靠每张上层牌压在下层边圈上的白色侧面/绿色底边、对称投影和逐层变暗体现。（非金字塔模式仍使用 `layerOffsetX/Y`。）
* 实测（默认 3 层）：每圈露出 左 43.31 / 右 43.31 px、上 51.97 / 下 51.97 px；4、5 层每圈同样相等。

### 默认值（v11）
`stackGridRef base`、`baseCols 7`、`baseRows 8`、`insetX/Y 0.5`、`rowStagger 0`、`ringBalance true`、`pyramidAutoGrow true`（层数多时底层自动加大，保证顶层至少 1×2）、`depthDarken 0.15`（逐层相乘）、`shadowStrength 0.95`、`shadowDX/DY 0.05/0.07`、`shadowSpread 2`、`boardOffsetY 0`。
* 三层 7×8 / 6×7 / 5×6 = 128 张；4 层 +4×5 = 148；5 层 +3×4 = 160（底层仍是 7×8，牌不缩小）。
* 牌宽 83.3 px（参考 89.6 px 的 93%），底层左右牌面边距 58.52 / 58.52 px（含右侧 2.5D 侧面的像素边距 58 / 51），顶层左右 145.14 / 145.14 px（4 层 188.44、5 层 231.75，均相等）；游戏区内上下 114.9 / 126.6 px（底边含 11.7 px 底座，视觉上相等）。
* 被压判定：半张缩进时每张下层牌都被上层压住一半，按逻辑重叠判为不可点（与画面一致），开局只有顶层可点；求解生成器、自动通关全部配置通过。
* 金字塔里各层外圈一开始都可见，字母组不再强制放到最高层（否则顶层几乎全是字母），随机分布在可见牌上。
* 参考视频的结构（下层每侧少一列、同砖块位置）保留为可选：`stackGridRef top`、`insetX -1`、`insetY 0`、`rowStagger 0.5`、`baseCols 6`。

## 第十轮：碰撞消除粒子（逐帧实测，v15）

用户反馈：两牌在中间碰撞消失时的粒子“不如参考好看、数量偏少”。方法：对 11 次配对各取汇合前 0.1 s ~ 汇合后 1.0 s，30 fps 原分辨率（360×640）逐帧分析，并以汇合点 (169,375) 为中心 240×200 放大 3–4 倍目测；树叶像素用颜色阈值（深绿 G>R+22 且 G>B+12 且不过亮，或黄绿）分割，减去汇合后 1.4 s 同区域静态画面中本来就是绿色的像素（牌上的条子/绿底座，膨胀 2 px），再做连通域统计（scipy）。牌面宽在汇合时 ≈70 px，下文“牌宽”均指它。

* **哪些配对有**：11 次里 10 次都爆叶子；**#6 干扰字母 T（28.5 s）没有任何叶子**（只有边框/托盘泛红）。→ 新增 `decoyParticles`（默认关）。
* **数量**：连通域数在峰值帧为 28–48，静态残留噪声 10–16，即同时可分辨 20–35 团；叶片互相重叠会并成一团，放大逐帧人工数峰值帧为 25–35 片。→ 默认 **32 片**（旧版 12）。
* **发射**：汇合后 1–2 帧（+33~67 ms）已经满屏叶子，之后不再新增 —— **一次性爆发**，不是持续喷射。→ `particleEmit 40 ms`。
* **出生位置**：覆盖两张牌整体范围（上半部更密），不是只从接缝处冒出。→ 出生半径 ≤0.95×两牌半宽，均匀分布在牌面范围内。
* **寿命**：叶片面积在 +100~+500 ms 保持峰值，+600 ms 起下降，+730~830 ms 降掉 90%。→ `particleLife 850 ms`（每片 0.72–1.05 倍随机），最后 25% 淡出。
* **外形**：细长尖叶（柳叶/竹叶形），长:宽 ≈4–5:1，微弯，叶尖细长、叶柄端圆钝；**以叶脉为界两半深浅不同**（一半受光一半背光），叶尖偏亮，部分可见浅色叶脉；无描边。
* **尺寸**：连通域长轴（含透视压扁/部分遮挡）10/50/90 分位 = 7.7/16.9/37 px，即 0.11/0.24/0.53 牌宽；最长的叶子 ≈60 px ≈0.85 牌宽；大小差异很大，且随时间变小（后段多为 10–20 px）。→ 叶长 0.25–0.95 牌宽（偏小的幂分布），寿命内缩小到 ≈0.55。
* **颜色**（叶片像素 k-means 4 类）：`#1c4c20` 16%、`#357d3f` 39%、`#588f59` 29%、`#83b785` 16%；最亮 95 分位 `#94cb76`。→ 深 `#1d4f23` / 浅 `#5fa257` / 叶尖高光 `#c3e38c`，每片在深浅之间取 8 档之一。
* **运动**：叶团从两牌范围向外扩张 —— 左缘（5 分位）-62 px（+100 ms）→ -100 px（+600 ms）→ -130 px（+800 ms），约 0.9–1.0 两牌半宽；前段**整体上扬**（+100~300 ms 上沿到中心上方 55–80 px，下沿只有 45–55 px），后段**下坠**（+600~800 ms 下沿到 80–120 px）；叶片绕两牌旋转着散开（旋涡）。相邻帧同一片叶子的朝向和宽窄明显变化，经常变成一条细线 —— 是**3D 翻滚**（像纸片一样翻面），不是平面旋转。
* **层次 / 特效**：叶子在牌的前面；**没有**辉光、闪光点、光线拖尾、白色闪光圈；略有运动模糊（视频压缩所致）。

本工具 v14 的问题：12 片、单一颜色的对称叶形、几乎同样大小、在平面上绕圈，所以显得少且“平”。

v15 改动（国风）：

* 叶片：离屏预渲染贴图（8 个色档 × 微弯不同），双色叶面（受光半边由叶柄到叶尖渐亮、背光半边更深）+ 浅色叶脉 + 受光边缘细高光；画面逐片 `drawImage`（批量贴图，不再每帧每片建渐变/路径）。

* 新设置（「动画」分组）：数量、整体大小、最小/最大叶长、宽长比、整体速度、旋涡、扩散、上扬、下坠、自转、翻转频率、寿命、发射持续、辉光、运动拖影、三种颜色、托盘格弹出粒子比例、干扰字母是否爆叶。
* 中东风：同一运动模型；金色四芒星闪光（带柔光晕，不翻面只闪烁）+ 宽圆玫瑰花瓣（基部深红→外缘粉的径向渐变、外缘高光、瓣脉），默认 36 片。
* AE 导出：每次爆开一个预合成、每片一层；位置/旋转/不透明度之外，**缩放也做关键帧**（scale-x 含翻转，可为负），素材与画面同一外形（8 档）。
* 设置版本 15：本地旧存档中仍是旧默认值的粒子参数（数量 12/14、颜色、大小 1.4）换成新默认；自定义值与导入的 JSON 保留。

### 第十轮复核：叶子“柔和 / 丝滑”（v15 定稿）

* **轨迹实测**：参考 #2 配对（10.40–11.25 s）中心 240×200 区域，`minterpolate=fps=60:mi_mode=mci` 插帧到 60 fps，把每帧绿叶掩膜按时间着色叠加（早蓝→晚红）：轨迹是**向外张开的弧线**（不是直线放射），起点在两牌范围内；蓝段（前 ~150 ms）短而粗、位移大，红段（后段）长时间停在外圈附近、只缓慢漂移 —— 即**强 ease-out：先“弹”出去，后像羽毛一样飘**。叶片沿弧线还有轻微左右摆动；朝向连续变化，没有跳变。
* **外观**：参考叶片边缘柔和（无深色描边），两半明暗差小，叶尖偏浅黄绿，略透，叶子整体微弯、左右不对称；快速段有沿运动方向的轻微拖影。
* **实现（`particleState`，完全由“出生时固定的参数 + 当前时间”解析计算）**：
  * 径向：`r = r0 + dr·ease(k)`，`ease(x) = (1−e^(−d·x))/(1−e^(−d))`，`d = particleDrag`（默认 3.2）；旋涡角也用同一 ease（角速度随阻尼衰减），所以路径是向外张开的弧线。
  * 上扬用 ease-out，下坠 `gravity·k²`，越到后面越明显。
  * 飘动：垂直于径向的两组正弦叠加（频率 `particleSwayFreq`≈1.4 Hz 及其 ~1.0×/0.6×变体，幅度 `particleSwayAmp`=0.12 牌宽，出生后 25% 寿命内渐入）。
  * 平面自转：匀速 + 低频正弦摆动；3D 翻滚：相位 `fl + vfl·t + 0.8·sin(低频)`，叶宽 = cos(相位)（沿叶长轴翻面），叶长轻微 0.88–1 摆动。
  * 平滑出现 / 消失：smoothstep 长出（前 6%）、缩到 55%、smoothstep 淡出（62%→100%）。
  * 每片的“噪声”只是出生时定下的相位/频率，之后不再取随机数 → 任意渲染帧率（30/60/144 fps）、AE 逐帧采样都在同一条连续曲线上，无步进/抖动。`test/particles.mjs` 检查相邻 20 ms 位移无跳变。
  * 外观：叶片贴图改为不对称微弯、无描边、两半明暗差小（背光半边 0.8×）、整体 ~0.95 不透明，边缘柔化 `particleSoft`=0.7（贴图级高斯模糊），运动拖影 `particleBlur`=0.5（同一轨迹上 9/18/27 ms 前的 3 个残影，沿速度方向）。
* **新设置**：减速/ease-out 强度、飘动摆幅、飘动频率、粒子不透明度；翻滚速度（原翻转频率，默认 2.2→1.3）、自转默认 2.5→1.8 rad/s。
* **AE**：粒子轨迹本来就逐帧烘焙（每个录制帧一组位置/旋转/不透明度/缩放 x,y 关键帧），与画面使用同一 `particleState`，因此与画面一致。
* **验证**：`samples/burst_compare.mp4`（左参考插帧 60 fps、右本工具 60 fps 逐帧，0.5× 慢放）、`screenshots/compare_burst_sequence.jpg`、`compare_burst_peak.jpg`。

工具实现（v17）：

* 点下第二张的那一刻（`clickTile` 触发配对、生成碰撞区）就规划抬指后的路线，与松开动作同时开始（`handAvoidDuration` 默认 450 ms，按路程加长，ease-in-out）。
* 方向 `handAvoidDir`：`next`（默认）此刻就选好下一组，若其第一张在碰撞区外 → 沿绕开碰撞区的三次贝塞尔弧线去它下方悬停；否则停到区旁。`auto` 同参考：往下/最近侧边退到区外（可半出画）。另有 向下/左下/右下。
* 路线起步方向 = 从碰撞中心指向手指并偏向下方，逐点检查：一旦离开碰撞区就不再回到区内。
* `handAvoidWait=burst`（默认）：在区外等碰撞+爆开结束（`flyDuration+burstDuration+handAvoidHold`）再点下一张，与参考的 ≈1.9 s 节奏一致；速度倍率 >1 时等待按比例缩短。
